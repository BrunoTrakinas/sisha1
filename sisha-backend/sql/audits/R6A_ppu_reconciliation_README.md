# R6A — draft atomic PPU receipt reconciliation
- Reuses the R2 deterministic planner and receipt accounting trigger, R5 snapshot chain and existing import audit and receipt events. No separate operational table.
- R6A only accepts summarized reports with no SN, excludes entire PNs with any serial evidence, and requires complete-report confirmation and actual observation dates. The legacy date needs documentary reference. No guessed date from file metadata. Native serialized import and Livro update are not yet homologated with this transaction.
- Feature flag PPU_RECEIPT_RECONCILIATION_ENABLED remains off until R6B/R7/R8. No automatic fallback after activation. Do not deploy with flag on until a complete UI and exclusive writer strategy are ready.
- On apply: locked context fingerprint, raw net growth and location-policy limits, receipt identity/quantity guards, existing accounting trigger, events, atomic stock replacement and snapshot. Reimport same hash returns existing active snapshot; historical file refused. SQL checks bounds, not full deterministic policy correctness; only trusted backend can execute RPCs. LOCREC conservative single-line evidence; historic LOCREC reconciliation remains separate.
- Before apply to production: PostgreSQL integration tests including transaction rollback, invalid plans, concurrent legacy imports, repeated file, permissions and lock contention; verify audit middleware on interrupted HTTP response and runtime DB privileges; R7 date/completeness form + report preview, confirm older date and new date; validate summarized ODS parser against original row count and ignored lines, serial search from Livro. Review SQL full-join and plan location attribution with explicit fixtures; validate service-role RPC runtime. R6B required before enabling. Do not perform live stock import here.
